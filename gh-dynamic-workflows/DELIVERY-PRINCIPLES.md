# Streamlined, work-conserving delivery

Approved reconciliation, 2026-10-24: continue independent authorized construction,
serialize shared-environment mutation rather than all development, replan only
when needed, and use targeted Network/Infrastructure Security review.
Deployed verification remains mandatory for assignment acceptance.

## Delivery principles

1. Localize blockers to the actual operation, component, flow and criterion.
   Drain independent authorized tasks and later approved sprints. Sprint order
   is not an implicit dependency; optional `sprint.dependsOn` requires full
   acceptance of the named sprints. Preserve genuine prerequisites.
2. Deploy the azd walking skeleton early. Preserve origin's first-sprint
   skeleton dependencies and deployed acceptance requirements. Local checks,
   fixtures and accurate failure reports never establish deployed acceptance
   or release dependents.
3. Construction can run concurrently, subject to declared task resources and
   ordinary permissions. Construction owners provide actual checks and an exact
   committed revision or immutable build artifact; they do not mutate the shared
   deployed environment. Existing DevOps and E2E loops deploy and verify that
   exact candidate under one shared environment lock before original assignment
   reviewers and acceptance. Never deploy an unrelated mutable checkout.
4. Replan only a material dependency, contract or scope change using existing
   architecture/planning roles. Do not impose continuation amendments,
   exhaustion audits, disposition ledgers or another arbitration chain.
   Idle capacity does not authorize new features, repeated reports or busywork.
5. Preserve accepted work, partial sprints, unresolved criteria and exact unblock
   conditions in an incomplete delivery checkpoint. Do not retry unchanged
   denials, reset explicit limits or repeat uncertain external effects.
   Entered partial sprints count against an explicit sprint limit.
6. Network/Infrastructure Security reviews affected network exposure, routing,
   private connectivity, identity/access configuration and relevant dependency
   CVEs. No broad red-team campaign or invented controls. Unchanged or
   inapplicable security scope requires no findings. All mandatory corrections
   still require original requirement/approval grounding and falsifiable failure
   reasons; demonstrated defects additionally require evidence.

## Boundaries

Cancellation, global safety/authority restrictions, credentials and CLI
permissions remain binding. A localized failure permits unrelated authorized
work, not an authority bypass. Execution errors remain errors and are raised
after independent work drains, with an additive durable checkpoint.

SDK journals provide best-effort replay, not exactly-once external effects.
Runs require the `work-conserving-v1` delivery contract; preserve older histories
and explicitly start a new compatible run rather than replaying old acceptance.
Studio remains read-only. Checkpoints do not claim a live SDK pause or authorize
cross-session database writes.

Optimize time to a working flow, critical-path progress, integration feedback
and fewer unnecessary interruptions, not role calls or completed cards.
